# container-gateway

一个让程序安全地“借用”Docker 容器的统一入口。

Docker 是一种轻量级的隔离运行环境。直接用它很强大，但也意味着把机器的管理权交出去。这个项目在 Docker 前面加了一层受控入口：使用者通过普通的 HTTP 请求创建容器、运行命令、传文件、访问容器里的服务，用完后销毁；管理者则保留镜像、资源、时长和操作记录的控制权。

## 它解决什么问题

很多场景都需要在隔离环境里执行任务：跑一段脚本、处理文档、做浏览器自动化，或者给不同系统提供临时运行环境。但直接开放 Docker 会带来几个现实问题：

- 使用者能看到并操作机器上已有的容器，而不只是自己的任务；
- 很难限制每个任务能用多少内存、CPU，以及能运行多久；
- 出了问题没有清晰的操作记录；
- 容器用完后容易忘记清理。

`container-gateway` 把这些问题收拢到一个入口里：调用方只拿到一组被允许的操作，容器按设定规格创建、到期自动回收，所有操作都留下记录。

## 它是什么

可以把它理解成“容器管理员 + 安全门卫”：

- 对内，它负责创建、启停和销毁容器，执行命令，收发文件，并把容器里的 HTTP 服务暴露出来；
- 对外，它只提供一个 HTTP 地址和一份访问凭证，调用方不需要接触 Docker 本身；
- 部署上不绑定某一种网络环境，内网、公网，或经反向代理、负载均衡、VPN 接入都可以。

## 主要功能

- **容器生命周期管理**：创建、启动、停止、销毁容器，流程简单可预测。
- **命令执行**：在容器里跑一次性命令，也支持持续输出的任务，并能拿到输出结果和退出状态。
- **文件交换**：向容器上传文件，或从容器下载生成的文件。
- **服务访问**：通过同一个入口访问容器里运行的网站或接口，不必为每个容器端口单独开放网络。
- **安全边界**：访问凭证、镜像允许清单、资源配额、到期回收、操作记录，以及以普通用户身份运行、只读系统盘等加固。
- **多机与监控**：可以管理多台 Docker 机器；附带一个可选监控组件，方便接入现有监控系统。

## 适用场景

- 给团队成员或业务系统提供临时、隔离的运行环境，同时不暴露 Docker 管理权限。
- 在服务器或云主机上运行脚本、文档处理、浏览器自动化等任务。
- 需要在内网、公网或混合网络里，通过一个统一入口管理分布在不同机器上的容器。
- 需要限制资源使用、自动清理过期容器，并保留操作记录以便追溯。

## 快速上手

先准备一台 Linux 机器，并安装 Docker、Java 21 和 Maven。整体体验是“获取代码 → 构建安装 → 用凭证调用接口”。

1. **获取代码**  
   在 GitHub 仓库页面点击 **Code**，选择 Clone 或 Download ZIP，然后进入项目目录。

2. **构建并安装**

   ```bash
   mvn -q clean package
   GATEWAY_PORT=3010 JAR_SRC=target/container-gateway.jar ./scripts/install-gateway.sh --restart
   ```

   安装脚本会生成访问凭证、写好配置文件，并把服务注册到系统中。它默认使用端口 `18090`；这里显式设为 `3010`，以便和下面的健康检查一致。

3. **确认服务已运行**

   ```bash
   curl http://127.0.0.1:3010/healthz
   ```

   看到状态为 `UP` 就可以开始使用了。

4. **开始使用**  
   从 `/etc/container-gateway.env` 读取访问凭证，然后按 [`docs/developer-guide.md`](docs/developer-guide.md) 的顺序：创建容器 → 执行命令或传文件 → 销毁容器。Java 用户也可以直接使用 [`client/`](client/) 目录里的客户端库；更完整的示例见 [`examples/README.md`](examples/README.md)。
